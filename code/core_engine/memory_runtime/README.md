# 三层记忆运行时

**最新修复**：公开接口由统一定义生成，区分9类操作、10类记录、引用命名空间及三种版本。正式流程把实际正文分段、附原文来源写入同一三层库；正文改写不再导致空库被判成功。队列完成、正文覆盖与方案对齐分别报告；摘录不是当前世界事实声明。288项本地测试通过，见[修复说明](../docs/verification/接口职责统一与正文记忆修复_2026-10-22.md)。以下默认流程仍停用正文内容校验和自动审核。

**最新开发策略**：正式event_first生成已移除正文内容校验和自动审核，保留数据完整性检查。数量来源与限定词在生成前提供，引用原样展开；没有正文来源的记忆投影记录缺项，不伪造来源或阻断写作。事件状态属于方案推演，不能视作正文语义认证。见[变更说明](../docs/verification/正文免校验与数值来源生成_2026-10-22.md)。

**2026-10-22默认写作更新**：正式入口现在使用事件方案→状态推演→冻结→正文→事件与正文共同提交→记忆投影。新章节不再调用正文记忆提取和独立事实重判；分层仍沿用三层存储。已有小说的只读记忆检查继续使用原提取流程。见[事件先行改造说明](../docs/verification/事件先行写作流程改造_2026-10-22.md)。

新流程支持版本化状态变化、不可变事实保护、人物知情来源及世界状态与人物旧认知分离。准备中的事件不算已发生，正文失败不提交候选状态。默认开启event_first；显式关闭只用于旧流程兼容，不会自动回退。

这是从第1章连续测试中收拢出的记忆模块。已有小说的记忆检查入口是根目录 `check_memory.py`，接口为 `MemoryEngine.advance/recall`。正式写作入口 `write_novel.py` 已通过 `writing.py` 接入同一记忆引擎，直接加载本目录 `src`，不依赖测试快照。现有小说检查与新写作相互独立，记忆测试不能替代完整写作质量验收。

## 固定规则

- 工作、近期、长期是三个逻辑集合；检查点文件是恢复记录，不是每章新建一座记忆库。
- 存储没有每属性16条上限。模型只判断重要性，程序精确分配工作上下文字节；超出者逐级降级或推迟召回，不删除。
- 完全相同的新增/更新按幂等操作处理：先校验字段、来源和更新版本，不改变原记录、条目版本或层级，将新引用记入 `no_change_observations`，不因无变化操作拒绝整批。冲突当前值、非法来源和过期版本仍会拒绝。
- 类别和已有状态身份由程序持有。模型回显的改类请求不应用到原记录，并记录在转换日志；非任务容器不会因片段已完成而变成整条 `task/completed`，事实陈述保持原类别并接受独立证据复核。新增当前状态与全库中精确同主体、同属性的已有当前状态重合时，由程序转成带正确编号/版本的更新，不做近似身份猜测。底层存储仍拒绝直接改类，保留第二道校验。
- 任务的 `active/pending/ongoing/in_progress` 统一为未完成状态 `planned`，不会因此推断任务已经完成或取消。类别与状态的组合在程序中统一处理并记录原始意图；未知状态仍由严格校验拒绝。
- 新属性的显示名与存储标识分开。数字、中文、空格、过长名称由程序生成稳定标识；原标签保存在 `attribute_labels` 和转换日志中。空值、错误类型仍应拒绝。
- 完成状态属于模型明确选出的任务片段，与外层记录类别分开。保留原句、类别、来源及其它片段；只有整条 `task` 才更新整体任务状态。
- 标为完成可关联已经入库的当前证据记录，仍要求本章证据、有效引用、版本和无循环。`superseded` 仍要求本章新增或更新的替代记录。
- 明确区分格式修复、未决问题复核和事实变化。复核只能保留未证实安排或继续阻断，不能发明新事实。修复后出现的新未决问题重新进入复核，最多3轮；整次时效整理共享一次格式修复预算，不因切换步骤而重置。
- 常见目标/替代引用错误合并反馈。已经更新的条目不是时效整理可再修改的旧候选。短编号只做精确映射，不猜测相似编号。
- 时效候选清单由程序绑定成一个带哈希的批次，模型回传 `checked_batch_token` 确认；程序将其映射回原候选范围，避免模型抄长编号列表时混入本章新增条目。错误或冲突批次不能通过。这只是范围确认，不证明模型逐条判断正确。原始远程回复和映射都留档。
- 同一条记忆内，未证实的片段可保持原样，其它有证据的片段可独立更新。保护与冲突检查精确到片段，禁止把一处不确定扩成整条拒绝；也禁止修复时顺带修改受保护片段。
- 新增/更新记录，以及使旧片段失效，都须经过额外的独立证据复核。复核只看原状态、拟变更片段、替代记录和已绑定的本章原句；不能把提案理由本身当证据。没有直接依据的变更写入 `withheld_memory_mutations`，继续保留原状态；其它合格新增或片段可以提交。暂缓的变更数在结果与逐章报告中明确显示，不视为全部提案正确。
- 提取、时效整理、分层全部成功才提交下一检查点。失败保留上一状态与待处理章节；检查点完整写入后原子改名，不覆盖已有提交。网络失败不自动重试。
- 召回使用当前查询、中文滑动双字词及同主体关联，不强制把全部工作记忆塞入问答。历史片段明确标注，召回不恢复其当前效力。
- 召回同时读取所选记忆已经绑定的原句，不重新打开小说正文；证据视图另限24000字节。复合问题按子问题为相关记录优先选择不同原句，避免一条摘要的首段证据挤掉另一问所需的动作。省略项明确记录，旧原句不自动代表当前状态。
- 召回先生成草案，再以相同记忆与证据独立复核身份关联、时态、矛盾和漏读。草案不作为事实依据。常见的独立历史引用字段只有在每个编号确实指向本次历史记录时才能合并；未知编号和其它未知字段仍拒绝。格式错误可要求重新输出，草案和复核共享一次修复预算；网络错误不自动重试。二次复核降低错误概率，不保证语义永远正确。

## 使用

运行本地回归：

```powershell
python -X utf8 memory_runtime/test_regression.py
python -X utf8 memory_runtime/test_writing.py
python -X utf8 memory_runtime/test_story_review.py
```

检查已有小说（先不调用模型）：

```powershell
python -X utf8 check_memory.py --input <小说状态JSON> --output <新的输出目录> --through 12 --preflight
```

实际调用使用同样参数并将 `--preflight` 改为 `--allow-remote`。可用 `--questions` 提供“章号→问题”映射；不读取评判答案。沿用本会话授权的严格连接配置读取器，不在导入、预检和测试时读取密钥。输出费用使用历史单价估算，不是账单或当前报价。

同版本恢复可加 `--resume <checkpoint_XXX.json或pending.json>`，使用新的输出目录。原小说和运行时哈希必须一致；版本变动需要显式迁移，禁止悄悄把旧状态当成新版本从头成功。

### 正式写作接入

当前默认流程以本页顶部更新及事件先行改造说明为准。下列“正文后提取”的段落描述保留的event_first=false兼容路径，已有小说检查仍适用原记忆引擎。

`python -X utf8 write_novel.py` 使用新模块。规划与写作读取工作记忆，并按查询检索近期/长期记忆、历史标签和已入库原句；没有恢复为有16项上限的旧属性结构，也没有先把上一章工作记忆整体降级。写作上下文的当前记忆、历史和原句分别有32000、6000、12000字节预算，整体超过84000字节明确停止。

正文先连同待处理标记原子保存，再运行记忆提取、独立证据复核、时效整理、分层；全部成功才提交记忆。按用户最新要求，记忆失败不暂停正文：保留原正文和前一记忆提交，记录连续待处理队列，下一章生成后再按顺序补处理，遇失败结束本轮补处理。不会立即重发失败网络请求，也不会跳过旧章把后章假称已入库。规划和写作会收到明确的记忆滞后范围及最近正文。正文完成与记忆齐全分别报告，记忆失败不导致已完成正文被记作未完成；质量判断仍不自动通过。

正文审核使用 `StoryReviewAgent`：仅漏 `suggestions` 且原有决定、问题和引用校验有效时，在本地补空建议列表，不重新请求模型改变判定。其它格式错误仍至多修复一次，原有有效决定与问题在格式修复中锁定。若存在问题提案，再进行一次独立语义复核，分为确认问题、写作建议、仍待核实；确认和转建议均要求正文与所引参考的逐字证据。原提案、复核理由、引文和被转为建议的意见均保留。没有问题时不增加复核调用。

独立复核无法完成、引文非法或判断不确定时，保持待核实且不批准，不能因复核失败清空问题后自动通过。二次复核的网络异常不立即重试；格式问题至多修复一次。主审核接口本身失败仍保留审核任务；二次复核不确定则保留意见，正文可以继续。`result.json` 与问题清单的 `story_review_counts` 分别列原提案、确认、待核实、转建议数；这些仍是模型判断，不是人工认证错误数。

恢复使用 `python -X utf8 write_novel.py --config <原配置> --resume <上次result.json中resume_checkpoint指向的文件>`，可加新的 `--output`。默认创建新目录，保留上次记录。先尝试补齐记忆，失败仍可续写；未完成正文审核单独处理。只读检查入口的旧快照、旧写作状态不能直接作为新写作断点。运行时和小说计划须一致，费用只统计本次调用，父运行另行保留。

## 验证边界

程序能控制结构、容量、事务和恢复，不能保证模型语义判断永远正确。遇到实际证据缺口应停在待处理状态。时效检查目前覆盖检索到的旧记录，省略的编号在报告中保留；不是全库语义认证。单部现有小说的记忆测试也不等于新小说写作质量通过。

原始失败轮次和最终固定版本复验分别保存；中途修过代码的接续链不记作最终版本一次跑通。
