# 四、通用可用性（H1–H9）

> 填写人：＿＿＿＿＿＿　复核人：＿＿＿＿＿＿
> 只改后 4 列；「编号 / 问题 / 考察目标」由 `merge.py` 校验，改了会合并失败。
> 9 题同属一人时，注意每题的小问要逐项回答（H1 五态、H3 六项控制）。

| 编号 | 问题 | 考察目标 | 实测结果 | 现象与证据 | 判定依据 | 改进建议 |
|---|---|---|---|---|---|---|
| H1 | 空状态、加载、成功、拦截、出错这 5 种状态分别长什么样？发送问题后每个阶段都有提示吗？能否一眼区分？ | 系统状态可见；状态设计完整 | 部分通过 | 空状态：书架空着写「书架还是空的」，作品没正文时写「故事，正待落笔」；加载：按钮变「正在创作…」，下一行「本批次已完成 0 / 1 章……正在准备正文」，但正文区还停在「故事，正待落笔」，两边对不上；完成：顶部四个数字（1 / 20 章、1,379 字、52 条记忆、5%）；出错：顶部一条英文横幅「Provider transport failed; delivery and billing may be unknown」；写什么内容都直接生成，没有「被拦下」这一态 | 每个阶段都该让人看得见、分得清，而且前后说法要一致 | 正文区跟着显示「正在写第 1 章」并给进度和停止；把英文横幅换成中文；补内容被拦下的说明 |
| H2 | 界面和提示里有没有出现"token、API、timeout、500、prompt"等技术词？ | 使用用户语言 | 不通过 | 首页最大的按钮是「配置 API Key」；设置里的「模型服务」满屏是 API Key、模型名称、Base URL 和「测试连接并保存」；点生成弹的确认框，三栏都是 token（预计输入、预计输出、预计合计），下面标着每百万 token 的单价；失败时横幅写着英文「Provider transport failed; delivery and billing may be unknown」 | 该用写作者听得懂的话，别把技术词摆到台面上 | 改成「填写模型密钥」「预计字数和费用」，token 和单价收进「计费详情」；模型名保留，旁边补一句「由 DeepSeek 提供」；失败提示改成中文 |
| H3 | 能否清空对话、编辑或撤回上一条、重新生成、中途停止、删除历史、把设置恢复默认？ | 用户对对话和设置的控制权 | 部分通过 | ①删除：侧栏每本书的「⋯」里有「置顶」「删除作品」，删除需二次确认，删掉后在废案箱能看到移入时间，可「恢复到书架」或「彻底删除」，彻底删除还会再确认一次；②编辑或撤回：没有，章节生成完改不了；③重新生成：有，「重新生成本章」可以写意见；④中途停止：没有，生成中按钮只剩「正在创作…」；⑤删除历史：只能整本删进废案箱，没有单独的「清空」；⑥恢复默认：设置里只有外观主题、配置模型服务和退出登录，找不到 | 用户要能控制局面，也要能反悔 | 生成中加「停止」，设置加「恢复默认」，让章节能编辑或撤回 |
| H4 | 同一操作（发送、重试、清空）在各处的图标、文案、颜色是否一致？整体设计标准是否统一？ | 操作与视觉一致 | 部分通过 | 同一件事三个名字都摆在同一屏里：侧栏大按钮写「开始一个新故事」，书架标题旁写「创建新的作品」，点开弹窗又变成「创建作品 ↗」；生成也是三种：创作台「预估并生成下一章」、确认框「继续生成」、章节旁「重新生成本章」；删除在侧栏「⋯」菜单和确认框都叫「删除作品」，废案箱里叫「彻底删除」 | 同一个动作该用同一种说法 | 统一成「新建作品」「生成本章」两组词，删除和彻底删除分开说清 |
| H5 | 空输入或超长输入时点发送会怎样？清空对话等危险操作有没有二次确认？ | 必填校验与危险操作防护 | 部分通过 | 创建弹窗里章节和字数已经填好 10 和 10000；书名和构想都空着直接点「创建作品」，弹窗不关，只在书名框上方弹出一个带橙色感叹号的小气泡「请填写此字段。」，页面里没有别的提示，也没说清还缺故事构想；文风要求旁边写着「已输入 0 / 2,000 字符」，超了会不会拦住没说；删除作品有确认，彻底删除还要再确认一次 | 该提前把错误挡住，危险操作要多问一句 | 把提示放进页面里（按钮上方一行字，指出缺哪项），空着时把创建按钮置灰 |
| H6 | 不会提问的新用户，界面上有没有示例问题、可选项或设置说明？ | 降低记忆负担 | 部分通过 | 第一次打开书架是空的，只写「书架还是空的」，没有示例；创建弹窗里书名和构想的占位文字是「为你的故事取一个名字」「谁是主角？故事发生在哪里？有什么冲突正等待发生？」，章节和字数有默认值；文风设定和写作 Skill 标着「可选」；模型服务里列了十个供应商可选 | 新用户该有现成的东西可以照着点 | 空书架放两个示例故事，点一下就能填进创建表单 |
| H7 | 从打开页面到得到第一个答案最少几步、几次点击？能否用 Enter 发送、Shift+Enter 换行？设置有没有默认值？ | 任务流最短与快捷操作 | 不通过 | 从打开到看到第一章：先配 API Key，再进我的作品，点侧栏「开始一个新故事」，填书名和构想（章节、字数有默认值），点「创建作品 ↗」，勾「我已阅读」，再点「预估并生成下一章」，还要在确认框里看一遍 token 和费用点「继续生成」，才真正开始；等了一分钟左右才看到正文，全程点了六次 | 第一次用应该尽量少几步就能看到结果 | 把「创建作品」和「生成第一章」合成一步 |
| H8 | 每个界面的方案是否最简单？主界面有没有与当前任务无关的元素？ | 极简设计 | 部分通过 | 新用户先进首页：一整屏是书本插画和「你的下一部作品正在等待第一章」，主按钮是「配置 API Key」，下面接着「规划 / 写作 / 记忆 / 存档」四步介绍和两行英文页脚；点进「我的作品」，又是一遍同样的四步流程和页脚，而真正能开始的「创建新的作品」只是标题右边一个小按钮。连着两屏，先看到的是品牌和流程，不是「开始写」 | 主界面只该留跟当前任务有关的东西，空状态尤其该把主操作放大 | 首页保留品牌介绍，书架页只留书架和「创建新的作品」并把按钮放大，流程图不要两页重复 |
| H9 | 制造一次出错（如断网）：错误信息是否说明原因和下一步？重试时要不要重新输入？多次失败有没有备选办法？ | 错误可理解、可恢复 | 不通过 | 断网后生成失败，作品页顶部只出现一条浅色横幅：「第2章未生成正文：[“Provider transport failed; delivery and billing may be unknown”]」——英文，还夹着「计费和交付可能未知」这种吓人的话，没说原因、没说下一步；页面上没有重试按钮，想继续只能自己再点「预估并生成下一章」、重新看一遍费用确认 | 出错要让人看得懂、知道下一步，还要能一键重试 | 横幅改成中文说明（如「第 2 章没生成成功：网络中断，可能已产生少量费用」），右侧放「重试」按钮，并保留已填的内容 |
