# 用户测试表（学生版）分栏填写与合并

课程原始表格：<https://github.com/bettermorn/ACMWDevHubPPT/blob/master/courseware/assignment/用户测试表-学生版.md>
本目录把它拆成"底稿 + 分栏 + 合并脚本"，供三人并行填写，合并时保证**问题原文与已填内容不被改动**。

## 文件

| 文件 | 作用 | 谁改 |
|---|---|---|
| `原始-用户测试表-学生版.md` | 从课程仓库原样提取的只读底稿（33 题 + 填写规则 + 场景 + 记录区 + 统计区） | 谁都不改 |
| `parts/01-P1-P5.md` | 产品价值 5 题 | 甲 |
| `parts/02-I1-I4.md` | 界面设计 4 题 | 乙 |
| `parts/03a-V1-V2.md` | 视觉设计 V1、V2 | 甲 |
| `parts/03b-V3-V4.md` | 视觉设计 V3、V4（间距/圆角/阴影、图标与插画） | 丙 |
| `parts/04-H1-H9.md` | 通用可用性 9 题 | 丙 |
| `parts/05-A1-A11.md` | 智能体专项 11 题 | 乙/甲 |
| `merge.py` | 按题号合并并校验前三列未被改动 | 汇总人执行 |
| `用户测试表.md` | 合并产物（首次运行 `merge.py` 时由底稿生成） | 汇总人最后补记录区/统计区 |

> 填写人按实际分工调整；上表只是默认切法。两人共用一个 part 文件时，各写各的行、不要动对方的行。

## 怎么填

1. 只改你负责的 `parts/*.md` 里对应行的**后 4 列**：`实测结果`、`现象与证据`、`判定依据`、`改进建议`。
2. `编号 / 问题 / 考察目标` 三列一个字都不要动 —— 它们是合并时的校验基准。
3. 不要新增、删除、重排题目行；不要改表头；不要把一行拆成多行。
4. 多小问的题（H1、H3 等）在同一格里用 `①②③` 分点写，仍保持一行。
5. 证据统一写**操作路径**（`页面 → 控件：现象`），不截图；路径要细到具体控件名。
6. 单元格内不要出现 `|`（会破坏表格）；需要换行时用 `<br>`。

## 怎么合并

```powershell
python docs\software\user-test\merge.py
```

脚本做三件事：

- 按题号把 `parts/` 里填好的行替换进测试表，**保持行序与表头不变**；
- 校验 33 行的「编号 / 问题 / 考察目标」与底稿逐字一致，任何一处被改就中止并打印文件、题号、列名；
- 打印每个维度已填/为空的题号，方便汇总人补漏。

首次运行会生成 `用户测试表.md`。之后再运行，会以**已有测试表**为骨架，所以第六～八节（场景准备、实测记录、统计与结论）里手工补的内容不会被覆盖。

## 汇总人最后要做的

1. 补齐第七节实测记录（把 `S` 编号按顺序登记，三人分段可直接拼接）。
2. 填写第八节统计表与"最严重的 3 个体验问题"、整体结论、自评。
3. 再跑一次 `merge.py`，确认 33 题无空白、前三列校验通过。
