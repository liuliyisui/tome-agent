# 章节标题占位词修复 · 2026-10-24

## 原因

规划输出失败时，`unplanned_packet()` 原先直接生成 `续写1`、`续写2` 等降级标题。章节提交把该字段写入作品状态，网页和 Markdown 导出再原样使用，因此用户看到了工作流占位词。

## 修复行为

新章节保存前，按以下顺序确定标题：

1. 保留本次规划返回的有效标题。
2. 若标题为空、只有章号或为“续写＋章号”等占位词，优先采用已有章节计划中的有效标题。
3. 若正文首行已有明确的 Markdown 标题或“第某章 标题”，提取其中的标题。
4. 仍无可用标题时，根据本章正文最多前 4000 个字符补拟标题；只进行一次请求，最多输出 128 token。
5. 命名请求失败、响应被截断或仍返回占位词时，用正文中的短句作为标题，不重试，不阻断正文保存。

正常标题不增加模型调用；异常标题的补拟请求通过现有 gateway 计入用量。标题会同时写入章节和当前章节计划，保存恢复、网页显示与导出使用同一字段。冻结的事件方案及其哈希不被事后修改，正文不因补标题而重写。

“续写传奇”这类具体标题不会仅因包含“续写”二字而被替换。修复覆盖事件先行和传统写作入口，不会自动重命名历史作品中的既有章节。

## 验证

新增 9 项离线测试，覆盖占位词识别、章号清理、大纲标题复用、正文标题提取、一次有界命名、异常降级、事件提交哈希不变、保存恢复和 Markdown 导出，以及传统入口。

完整应用回归：121 项，114 通过、7 项因未配置真实 PostgreSQL 而跳过。长篇入口回归：42 项，39 通过、3 项因缺少历史资产而跳过。未调用真实模型。
