### OBS-4（高）进程异常退出后残留 `operation.lock`，作品无法继续生成

- 复现步骤：
  1. 创建 1 章作品并启动生成；
  2. 在首章写入过程中强制结束服务进程（模拟断电、任务管理器结束进程、系统更新重启）；
  3. 重启服务并再次生成；
  4. 观察任务状态。
- 期望：服务重启后能识别并清理过期锁，作品正常继续生成；或至少在页面提供一次性的「解除锁定」操作。
- 实际：任务立即 `failed`，错误为「此作品有操作正在进行；确认没有运行任务后才能清理 operation.lock」。作品在页面上显示为 0 章，用户只能自行找到数据目录并手动删除锁文件后才能恢复。
- 影响：任何非正常退出都会让该作品在人工介入前完全无法继续创作；演示过程中一旦出现异常退出，无法在一分钟内恢复。
- 证据：
  - 崩溃后目录：`checkpoint.json`、`longform-runs/`、`metadata.json`、`operation.lock`（无 `longform-current.json`、无 `last-usage.json`）
  - 崩溃后任务：`{"status":"failed","error":"此作品有操作正在进行；确认没有运行任务后才能清理 operation.lock"}`
  - 手动删除 `operation.lock` 后重新生成：`completed`，第 1 章「无人之船」526 字
- 位置：`code/backend/inf_backend/service.py` 的 `operation_lock()`；锁文件不记录 PID 与创建时间，进程退出后无法判断是否过期

### OBS-1（中）首次生成前的费用预估显著低估实际 token 与费用

- 复现步骤：
  1. 新建 1 章、目标 800 字的作品；
  2. `POST /api/books/{id}/estimate`；
  3. 确认生成，完成后读取 `last-usage.json`。
- 期望：预估与实际处于同一量级，能支撑「¥1 预算」判断。
- 实际：
  - 预估：输入 6066 / 输出 4100 tokens，约 ¥0.0225
  - 实际：输入 53953 / 输出 9337 tokens，约 ¥0.0913（off_peak 单价复算）
  - 偏差：成本约 4.1 倍，输入 token 约 8.9 倍
- 根因判断：`estimate()` 中 `base_input = 6000 + 2 * context_chars`、`base_output = target * 2 + 2500` 按「一次调用」估算，而实际单章链路发生 8–10 次模型调用，缺少按调用次数的放大系数。
- 影响：首次使用时用户会被明显低估的数字误导；`pricing.status=live` 与 `basis` 的提示不足以抵消数量级偏差。
- 证据：`last-usage.json` 为 `{"calls":10,"input_tokens":53953,"output_tokens":9337}`
- 位置：`code/backend/inf_backend/generation.py` 的 `estimate()`
- 备注：第 2 次预估会自动参考上次实际用量，误差消失（预估 31920/4911，实际 31920/4911），说明缺陷只影响「无历史用量」的首次预估。

### OBS-2（低）目标章节数小于大纲条目数

- 复现步骤：创建 `chapters=1` 的作品并生成首章，检查存档 `book.plan`。
- 期望：1 章作品的大纲只包含第 1 章。
- 实际：`plan` 同时包含第 1 章「雪夜待信」和第 2 章「底账缺页」。
- 影响：不产生错误正文，但会多消耗规划 token，也让存档大纲与「全书 1 章」的目标不一致；页面未展示大纲，因此不影响界面。
- 位置：`code/core_engine/memory_runtime/writing.py` 的 `future_updates` 写入与规划窗口；`max_chapters=1` 时仍写入了第 2 章条目，需确认是规划窗口的有意行为还是校验遗漏。

### OBS-3（低）缺少 `favicon.ico` 导致控制台 404

- 复现步骤：打开页面，浏览器请求 `/favicon.ico`。
- 预期：返回图标或静默 204。
- 实际：404，浏览器控制台出现一条错误。
- 影响：仅影响观感与日志噪声。
