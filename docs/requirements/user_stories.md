# Tome Agent 小说生成 —— 用户故事与验收标准实例（现有功能）

> 本文档按 Tome Agent 现有实现整理，覆盖创建作品与书架管理、文风设定、网页端逐章生成、首章确认后批量续写、token 与费用预估、事实记忆、`write_novel.py` 连续写作等能力。每条用户故事按 INVEST 标准拆分，验收条件用 Gherkin 场景描述；内容只限于当前能从网页工作台、命令输出或作品存档观察到的行为。

## 故事 1：按自己想看的题材和走向生成小说

**用户故事：**

角色：作为一名只想看自己想看的故事的读者，  
功能：用一两句话描述题材、主角和走向，创建作品并在确认费用后生成第一章，  
价值：以便不用等别人更新，也不用将就平台现有的套路。

**验收标准（Acceptance Criteria - Gherkin 语法）：**

场景：用一段故事描述创建作品并生成第一章  
Given 首次打开工作台，没有任何作品，且本机已配置 DeepSeek 密钥  
When 输入作品名“听见物品的人”、构想“都市异能，女主能听见物品心声，轻松向，不虐主”、章节数 10、目标总字数 20000，点击“创建作品”  
Then 书架应新增这部作品并显示 0 / 10 章  
And 作品应保存所填写的名称、构想、目标章节数和目标总字数，且创建过程不调用模型  
When 点击“预估并生成下一章”  
Then 页面应显示本次预计的输入 token、输出 token、token 合计和人民币费用  
When 核对后点击“继续生成”  
Then 工作台应显示第 1 章的标题和正文，章节进度变为 1 / 10  
And 累计字数与事实记忆应随本章更新

## 故事 2：教材编辑用知识点生成故事示例

**用户故事：**

角色：作为一名教材编辑，  
功能：把知识点写进全书构想，先生成并阅读第一章，再批量生成其余章节的故事示例，  
价值：以便用故事例子把抽象知识点讲得更生动，而不是只依赖定义和习题。

**验收标准（Acceptance Criteria - Gherkin 语法）：**

场景：为知识点创建作品并批量生成故事示例  
Given 本机已配置 DeepSeek 密钥  
When 创建作品“机会成本示例集”，构想填写“围绕机会成本写 3 个生活故事示例，每章一个例子，语言通俗”，章节数 3、目标总字数 3000  
Then 书架应新增作品并显示 0 / 3 章  
And 作品存档中的全书构想应保存这段知识点要求，目标章节数和目标字数应分别为 3 和 3000  
When 生成并阅读第 1 章，勾选首章阅读确认项，确认合适后自动续写  
Then “本次输出章节数”应自动填入剩余章节数 2  
When 确认费用预估并点击“继续生成”  
Then 工作台应显示生成进度，并在完成后显示 3 / 3 章  
And 章节选择区应能依次打开第 1、2、3 章，事实记忆应随生成更新

> 说明：当前系统按一部作品连续生成，没有独立的短篇集或多故事批量模式；章与章之间可能存在人物、情节关联。验收只检查示例章节已生成、可阅读，每章是否独立、知识点是否准确仍需编辑人工筛选和修改。

## 故事 3：用文风设定统一作品口吻

**用户故事：**

角色：一名业余作者，  
功能：为单部作品填写文风要求和参考片段，并让设定从下一章开始生效，  
价值：以便后续章节保持相近的叙述风格，同时不改动已经写好的正文。

**验收标准（Acceptance Criteria - Gherkin 语法）：**

场景：保存文风并在下一章生效  
Given 作品《守灯人》已有第 1 章  
When 在文风面板填写不超过 2000 字的文风要求和不超过 6000 字的参考片段并保存  
Then 保存应成功，刷新页面后仍能看到这两项内容  
And 之后生成第 2 章时，writer 请求应携带该文风设定，planner 与 memory 请求不应携带参考片段  
And 第 1 章正文及其哈希应保持不变

## 故事 4：故事记忆可追溯，设定不丢

**用户故事：**

角色：作为一名希望前后设定保持一致的连载作者，  
功能：在每章生成后看到人物和物品的关键事实，以及它们的版本和正文出处，  
价值：以便后文能沿用同一设定，也能查到这个设定是从哪一章开始、在哪一章改变。

**验收标准（Acceptance Criteria - Gherkin 语法）：**

场景：事实变化时版本递增并保留旧值  
Given 第 1 章已记录“艾岚 · 眼睛颜色 = 棕色”，版本为 1  
When 第 2 章正文写明“药剂让她的眼睛变成金色”，并完成生成  
Then 工作台应显示当前值“金色”、版本 2、出处第 2 章和新引文  
And 作品存档的记忆历史中应能查到旧值“棕色”、版本 1 和原第 1 章出处  
And 未在本章提到的其他事实不应因这次更新而丢失

---

## 故事 5：连续写作并在目标处停止

**用户故事：**

角色：作为一名想一次写完多章、又不想逐章点击的作者，  
功能：把故事点子和目标写进配置，用一条命令连续生成，并在达到目标章节数或目标篇幅时自动停下，  
价值：以便一口气得到多章初稿，也能知道它写到了哪里、为什么停下。

**验收标准（Acceptance Criteria - Gherkin 语法）：**

场景：按目标章节数连续生成并自动停止  
Given 写作配置里写好故事点子和目标：`chapters=3`、`max_chapters=3`、`target_han_chars=3000`，并确认运行会产生 API 费用  
When 在 `code/core_engine` 下执行 `python -X utf8 -B write_novel.py --config novel_config.json --output runs/novel_demo`  
Then 系统应依次写完第 1、2、3 章，并在第 3 章后自动停下  
And 输出目录里应保留 `正文.md`、`问题清单.json`、`final_state.json`、`事件链.json`、`result.json`，以及 `working/` 下的逐章检查点  
And `result.json` 里应写明完成章节数、汉字数、停止原因、调用次数、输入/输出 token 数量和费用估算

## INVEST 自检说明

- **Independent（独立）**：5 个故事分别对应用户可独立操作的场景——读者点单、教材编辑生成示例、文风设定、故事记忆、爱好者连续生成。
- **Negotiable（可协商）**：页面布局、按钮文案和提示样式留给设计与开发协商；故事只约束用户可观察的行为、保存结果和错误提示。
- **Valuable（有价值）**：每个故事都对应明确价值——看自己想看的故事、知识点有故事例子、文风统一、设定可追溯、点子变成连续初稿。
- **Estimable（可估算）**：边界清晰，且均能对应到现有实现位置，例如 `create_book`、`save_writing_style`、`generate_longform`、`WritingSession`。
- **Small（小）**：每个故事只聚焦一项能力，配一个场景，适合放在一个迭代内完成并验收。
- **Testable（可测试）**：场景均给出具体输入、操作和可观察结果，包括章节数、字数、版本号、检查点字段、费用预估和错误提示，可直接转为自动化或人工验收用例；文学质量和教学内容准确性不在本故事集的通过条件内。
