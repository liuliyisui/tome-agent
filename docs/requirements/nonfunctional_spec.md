# Tome Agent 非功能需求规范

| 项目 | 内容 |
|---|---|
| 文档编号 | TOME-SRS-NFUNC-01 |
| 版本 | v1.0 |
| 状态 | 已评审，与功能规范配套 |
| 对应代码 | `code/frontend/`、`code/backend/tome_backend/`、`code/core_engine/tome_agent/` |
| 依据 | [功能需求规范](functional_spec.md)、[架构说明](../algorithm/ARCHITECTURE.md)、[验证记录](../software/VALIDATION.md) |
| 日期 | 2026-10-17 |

## 一、目的

本文规定 Tome Agent 在性能、可靠性、正确性、安全、可用性、兼容性、可维护性与成本上的质量要求，并给出每条要求的**可度量指标**与**验证方法**。凡当前版本无法证明的，明确标为“待验证”，不写成已完成。

## 二、性能（NFR-P）

| 编号 | 要求 | 指标 | 验证方法 |
|---|---|---|---|
| NFR-01 | 页面首屏可用（不触发模型调用） | 冷启动 ≤ 10 s，二次打开 ≤ 3 s | 本机实测启动到页面可交互 |
| NFR-02 | 单章生成时长可接受 | 参考：8 章累计 33 次请求、69.3 万 token；单章 1–3 分钟（含重试） | 读取作品目录 `generation-usage.json` 与 `book.json.attempt.json` 的 `turns` |
| NFR-03 | 注入模型的记忆体积有上限 | 当前事实默认 ≤ 24 000 字节（`Limits.fact_bytes`），超限中止并提示复核 | 构造超量事实，验证报错文案含实际字节数与上限 |
| NFR-04 | 单次工具调用返回有上限 | `read` ≤ 12 000 字符；`read`/`search` 各 ≤ 8 次、`correct` ≤ 3 次 | 单元测试覆盖预算超限分支 |
| NFR-05 | 单章工具轮次可控 | 默认 30 轮，可配 3–100；超限终止并保留工作副本 | 界面参数与 `--max-turns` 生效性验证 |

## 三、可靠性（NFR-R）

| 编号 | 要求 | 指标 | 验证方法 |
|---|---|---|---|
| NFR-06 | 存档写入原子化 | 任何写入失败后旧存档字节完全不变 | 断点注入 `os.replace` 失败，比对文件哈希 |
| NFR-07 | 失败不产生半成品正文 | 失败后 `book.json` 章节数不变，仅新增工作副本 | 制造校验失败，检查章节数与文件清单 |
| NFR-08 | 断点续写可用 | 从工作副本恢复后不重跑已完成章节，用时不超过剩余轮次 | 失败后勾选恢复，观察轮次与最终结果 |
| NFR-09 | 提交幂等 | 同一「章号:组ID」重放不重复写入 | 重放同一 payload，比对事实条数与历史归档 |
| NFR-10 | 单作品单写者 | 并发进入时被拒绝并给出可操作提示 | 两个窗口同时点击续写 |
| NFR-11 | 存档版本受控 | `schema_version` 不符、章节不连续、pending 残留一律拒绝加载 | 手工篡改存档字段，验证加载报错 |

## 四、正确性与一致性（NFR-C）

| 编号 | 要求 | 指标 | 验证方法 |
|---|---|---|---|
| NFR-12 | 每条事实可追溯到正文 | 100% 事实带「章号 + 引文」；引文必须逐字出现在该章正文 | 事后全量校验 `check_sources` |
| NFR-13 | 版本单调 | 同一标识的 `revision` 严格递增，旧值进入历史归档 | 单元测试覆盖更新与退休 |
| NFR-14 | 稳定标识不被覆盖 | 同一「主体 / 属性键」重复 `store` 必须失败 | 单元测试：重复建档报错 |
| NFR-15 | 校验失败可定位 | 报错包含组 ID、条目序号与具体字段 | 构造非法字段，检查返回结构 |
| NFR-16 | 生成与校验解耦 | 无模型参与时，同一存档的校验结果确定且可复现 | 连续两次运行校验，结果一致 |

**已知不满足项**：跨章数值一致性（人物年龄换算、日期间隔规则）目前无自动校验；已在功能规范 GAP-04 登记。

## 五、安全与隐私（NFR-S）

| 编号 | 要求 | 指标 | 验证方法 |
|---|---|---|---|
| NFR-17 | 密钥仅本地存储 | 密钥只出现在 `.env` 与本机环境变量；存档、导出、页面、日志均不含 | 全目录检索密钥片段，命中数须为 0 |
| NFR-18 | 密钥不外显 | 界面只显示“已配置/未配置”；`check` 不打印内容 | 运行 `check`，检查输出 |
| NFR-19 | 仅允许官方接口 | 地址必须是 `https://api.deepseek.com` 且无端口、路径、凭据 | 构造非法地址，启动应报错 |
| NFR-20 | 服务仅本机可访问 | 监听 `127.0.0.1`，不对局域网开放 | 外部设备访问应失败 |
| NFR-21 | 数据不出本机 | 只有正文与状态发往模型；作品、日志、用量留在本地 | 审阅请求体构造代码 |
| NFR-22 | 仓库不收录敏感数据 | 仓库内 `.env` 为空模板，无密钥；`data/books/`、`.venv/` 需有忽略规则（当前缺） | 扫描 git 对象中的密钥字样；检查 `.gitignore` |

## 六、可用性（NFR-U）

| 编号 | 要求 | 指标 | 验证方法 |
|---|---|---|---|
| NFR-23 | 安装路径短 | 三步：运行 `setup.cmd` → 填密钥 → 运行 `start.cmd` | 在干净 Windows 环境复现 |
| NFR-24 | 错误信息可行动 | 每条错误说明“缺什么/差多少/下一步做什么”，不出现裸异常 | 抽查 10 条主要错误文案 |
| NFR-25 | 界面语言与术语一致 | 中文界面，术语与文档一致（事实、归档、pending） | 走查四个页签 |
| NFR-26 | 费用需显式确认 | 网页需勾选确认；命令行需 `--allow-paid` | 不勾选/不带参数时不得发起模型调用 |

## 七、兼容性（NFR-K）

| 编号 | 要求 | 指标 | 验证方法 |
|---|---|---|---|
| NFR-27 | 运行时版本 | Python ≥ 3.11（本机实测 3.14） | 两版本各跑一次 `check` 与测试 |
| NFR-28 | 操作系统 | Windows 10/11；脚本使用 `%APPDATA%` 与 `.venv` 约定 | 本机验证；其他系统未验证 |
| NFR-29 | 存档向后兼容 | 结构变更必须升级 `schema_version`，旧版本被显式拒绝而非误读 | 加载旧/新格式存档 |
| NFR-30 | 外部依赖可锁定 | 全部依赖及其传递依赖版本固定，重装得到同一组合 | 对比 `pip freeze` 与 `requirements.txt` |

## 八、可维护性（NFR-M）

| 编号 | 要求 | 指标 | 验证方法 |
|---|---|---|---|
| NFR-31 | 分层清晰 | 前端不直接调用模型；后端只管服务与存储；核心引擎不依赖前端 | 代码审阅导入关系 |
| NFR-32 | 自动测试覆盖主路径 | 当前 32 项：单元 23 项 + 集成 9 项 | `python -m unittest discover -s tests` |
| NFR-33 | 测试离线可跑 | 模型调用使用 MockTransport，不产生费用 | 断网运行测试 |
| NFR-34 | 文档与代码同步 | 文档描述的工具集、参数默认值与代码一致 | 抽查 `tools.py`、`agent.py` 默认值 |
| NFR-35 | 格式可解析 | 全仓库 Markdown 表格无列数错位 | 脚本校验表格列数 |

**当前偏差**：全量跑测试时，一项 UI 集成测试因 Streamlit `AppTest` 默认 3 秒超时而失败（单独重跑 1.4 秒通过）。建议在 CI 中把该超时显式提高到 10 秒，避免把环境抖动当作缺陷上报。

## 十四、复核发现（2026-10-17）

对两份规范做代码比对时发现三处「文档写得好、代码没做到」的地方，按严重度排列：

| 编号 | 发现 | 严重度 | 影响 | 建议动作 |
|---|---|---|---|---|
| F-01 | 仓库**没有 `.gitignore`**；`.env` 已被 git 跟踪。已核实仓库内的 `.env` 是空模板（`DEEPSEEK_API_KEY=` 无值），247 个 pack 对象中没有任何一个含 `sk-` 开头的密钥；密钥只存在于本机工作副本（测试期填入） | 中 | 当前未泄露，但 `.env` 被跟踪意味着下一次 `git commit -a` 会把本地密钥一并提交；`git add .` 还会把 `data/books/`（存稿）与 `.venv/`（300 MB）加进仓库 | 补 `.gitignore`，并把 `.env` 改成 `git rm --cached` 后只保留空模板 |
| F-02 | 章节大纲被模型包成 `{"chapters": [...]}` 时，规划直接报「数量不符」，没有解包 | 中 | 规划阶段整轮失败，只能重跑并重复计费 | 在解析处兼容单键对象包裹的数组 |
| F-03 | 记忆引文要求逐字匹配，模型漏抄中文引号即整组被拒 | 中 | 单章可能连续被拒后放弃，浪费已用轮次 | 引文比对忽略引号与空白，命中后回填正文原片段 |

F-02、F-03 同时也登记在功能规范的 GAP-05、GAP-06。
