## 一、目的与范围

本文规定 Tome Agent 第一版必须提供、应当提供和明确不提供的功能，作为开发、测试与验收的共同基准。

范围限定为：单用户、本地运行、中文长篇小说、DeepSeek 模型、顺序逐章生成、本地文件存档。多人实时协作、在线账户、移动端、自动出版、模型微调不在本版范围内（见 FR-22）。

需求优先级定义：

- **P0**：不满足则产品不可用于演示与验收。
- **P1**：影响可用性，第一版应满足。
- **P2**：体验改善，允许排到后续版本。

状态定义：**已实现**（代码与测试均覆盖）、**部分实现**（主流程可用，边界未覆盖）、**未实现**（仅登记）。

## 二、术语与角色

| 术语 | 含义 |
|---|---|
| 作品（book） | 一部小说的完整单位，含构想、大纲、章节、叙事状态与事实账本 |
| 章节大纲 | 冻结后的章节卡，含 `title`、`goal`、`target_units` |
| 工具循环 | 模型在同一章内反复调用工具直到 `DONE` 的受限循环 |
| 事实账本 | 以 `主体 / 属性键` 为单位、带版本与来源引文的事实集合 |
| pending 组 | 提交后校验未通过、必须修复后才能结束本章的记忆变更组 |
| 工作副本 | 失败章节的中间状态文件 `book.json.attempt.json` |
| 作者 | 使用者本人，对正文与署名负责 |

## 三、总体用例

作者在本地网页中新建作品 → 生成四阶段规划与章节大纲 → 逐章生成正文 → 查看故事记忆 → 导出成稿。任一章失败时保留工作副本，作者选择恢复或重写。

异常路径：模型输出截断、记忆校验被拒、超出用量预算、进程中断、密钥缺失、存档损坏。全部异常均须给出可读原因，且不得写入半成品正文。

## 四、功能需求

### 4.1 规划（FR-P）

| 编号 | 需求 | 验收标准 | 优先级 | 状态 |
|---|---|---|---|---|
| FR-01 | 作品创建：以作品 ID、名称、故事构想、章节数、目标字数创建工作 | 作品 ID 仅允许字母/数字/下划线/短横线；ID 重复时拒绝创建并提示 | P0 | 已实现 |
| FR-02 | 四阶段规划：前提 → 详细梗概 → 幕结构 → 冻结章节大纲，逐阶段调用模型 | 每个阶段仅接受合法 JSON 与 `stop` 结束；阶段产物随作品保存，可在网页「故事与大纲」查看 | P0 | 已实现 |
| FR-03 | 章节大纲必须与请求章节数一致，每章含 `title` 与 `goal` | 数量或结构不符时拒绝保存并说明期望与实际 | P0 | 已实现 |
| FR-04 | 大纲冻结前后可人工编辑 | 未开始生成时可在网页编辑章节大纲 JSON 并保存；已生成章节后禁止修改 | P1 | 已实现 |
| FR-05 | 规划结果缓存 | 相同输入重复规划命中缓存，不重复计费；配置变化时拒绝使用旧缓存 | P1 | 已实现 |

### 4.2 逐章生成（FR-G）

| 编号 | 需求 | 验收标准 | 优先级 | 状态 |
|---|---|---|---|---|
| FR-06 | 章节工具循环：提供 `read`、`search`、`correct`、`write`、`update` 五个工具 | 工具按 `chapter_tools()` 声明校验参数；未知工具或参数不符直接拒绝 | P0 | 已实现 |
| FR-07 | 正文一次完整提交并做长度校验 | 长度须落在目标值的允许区间内；不合格时返回差额与「补充/删减」建议 | P0 | 已实现 |
| FR-08 | 完成判定：正文已提交、记忆更新成功、无 pending、最后回复为 `DONE` | 四条件缺一即不提交，并逐项说明缺哪一条 | P0 | 已实现 |
| FR-09 | 轮次与预算控制 | 每章工具轮次上限可设（默认 30）；超出即终止并保留工作副本 | P0 | 已实现 |
| FR-10 | 前文读取与检索 | `read` 只能读已存在章节；`search` 返回命中片段，均受调用次数与字数上限约束 | P1 | 已实现 |
| FR-11 | 已提交正文的受限修正 | `correct` 要求原文只出现一次；被记忆回执绑定的章节禁止修改 | P1 | 已实现 |

### 4.3 故事记忆（FR-M）

| 编号 | 需求 | 验收标准 | 优先级 | 状态 |
|---|---|---|---|---|
| FR-12 | 三类叙事状态：人物、历史事件、未来义务 | 三类均可新增与查询；未来义务可标记为已兑现 | P0 | 已实现 |
| FR-13 | 事实账本：以「主体 / 属性键」为稳定标识，保存值、版本、分类、认知状态、支持依据 | 同一标识重复 `store` 被拒；值变化必须用 `update` 并携带当前版本 | P0 | 已实现 |
| FR-14 | 来源引文：每条事实必须引用本章正文中的片段 | 引文未在正文出现即拒绝；事后校验仍要求引文与正文一致 | P0 | 已实现 |
| FR-15 | 旧值归档：更新或退休时保留旧值、替换原因与证据 | 历史归档可在网页「故事记忆」查看 | P0 | 已实现 |
| FR-16 | 提交校验：字段集合、键名格式、时间锚点、主观事实命名、不确定项 | 任一不符则该组进入 pending，并返回具体错误字段 | P0 | 已实现 |
| FR-17 | pending 修复：失败组必须用同一组 ID 重提 | pending 未清零时不得结束本章 | P0 | 已实现 |
| FR-18 | 幂等回执：成功组按「章号:组ID」记账 | 重放同一 payload 不重复写入，回执不一致时拒绝 | P1 | 已实现 |
| FR-19 | 记忆体积预算 | 注入模型的当前事实超过字节预算时中止并提示复核 | P1 | 已实现 |

### 4.4 事务与恢复（FR-T）

| 编号 | 需求 | 验收标准 | 优先级 | 状态 |
|---|---|---|---|---|
| FR-20 | 原子存档：写入临时文件后同盘替换 | 替换失败时旧存档与原文件保持一致，不出现半截 JSON | P0 | 已实现 |
| FR-21 | 失败工作副本：异常时保存 `attempt.json` | 副本含草稿、消息、追踪、已用轮次与错误原因 | P0 | 已实现 |
| FR-22 | 断点续写：可从工作副本继续本章 | 续写要求基线与正式存档一致、章号一致；不一致则拒绝 | P0 | 已实现 |
| FR-23 | 作品锁：同一作品同时只允许一个操作 | 重复进入时提示「此作品有操作正在进行」，并说明如何确认与清理残留锁 | P1 | 已实现 |
| FR-24 | 存档版本校验 | `schema_version` 不符、章节不连续、pending 残留的存档拒绝加载 | P0 | 已实现 |

### 4.5 全书调度（FR-S）

### 4.10 已知缺口（登记待办，不计入本期验收）

| 编号 | 缺口 | 影响 |
|---|---|---|
| GAP-01 | 编辑已提交正文后的记忆复核未实现 | 作者改写正文后，账本可能与正文脱节 |
| GAP-02 | 事实只增不减，无「退休」入口 | 长篇写作会持续逼近记忆体积预算 |
| GAP-03 | 无文件锁与输入 schema 校验 | 并发调用或多个窗口同时写入可能损坏存档 |
| GAP-04 | 生成器未做跨章数值一致性校验（年龄、日期差） | 年龄换算、间隔规则类错误无法自动拦截 |
| GAP-05 | 章纲被包成 `{"chapters": [...]}` 对象时误判为「数量不符」 | 规划阶段整轮失败，只能重试；实测已发生 |
| GAP-06 | 记忆引文不做标点归一化 | 模型漏抄引号即整组被拒，可能拖垮整章 |
| GAP-07 | 模型用纯文本收尾时直接判失败，无纠正重试 | 明明还有轮次预算，章节仍失败 |

## 五、用例

### UC-01 创建作品并生成大纲

- **角色**：作者
- **前置**：已完成安装，`.env` 已配置密钥
- **主流程**：填作品 ID、名称、构想、章节数、目标字数 → 勾选费用确认 → 生成分层大纲 → 系统完成四阶段规划 → 保存存档与缓存 → 页面提示并从侧栏打开作品
- **异常**：ID 重复 / 密钥缺失 / 模型响应非 JSON / 章节数与请求不符 → 提示具体原因，不保存半成品
- **后置**：作品目录出现 `book.json`、`outline-cache.json`、`planning-usage.json`

### UC-02 生成一章

- **角色**：作者
- **前置**：作品存在且未完成全部章节
- **主流程**：选择章节数（1）→ 勾选费用确认 → 开始续写 → 模型 `read`/`search` → `write` 提交正文 → `update` 提交记忆 → 修正 pending → 回复 `DONE` → 校验通过 → 落盘
- **异常**：长度不符 / 引文不在正文 / 记忆字段非法 / 轮次耗尽 → 保留工作副本并说明缺项
- **后置**：章节数 +1，事实账本与叙事状态更新，用量记录写入

### UC-03 失败后恢复

- **角色**：作者
- **前置**：存在 `book.json.attempt.json`，其基线与当前存档一致
- **主流程**：勾选「继续上次失败的章节工作副本」→ 开始续写 → 从上次轮次继续 → 直至 `DONE`
- **异常**：基线与存档不一致 / 配置变化 → 拒绝续写并说明需重新开始
- **后置**：工作副本在成功后转为正式存档

### UC-04 导出成稿

- **角色**：作者
- **前置**：至少一章已完成
- **主流程**：打开「导出」→ 下载 Markdown 或 JSON
- **后置**：得到与存档一致的成稿文件
