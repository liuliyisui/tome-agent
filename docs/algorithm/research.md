# 技术调研与选型

## 目标和方案

Tome Agent 面向长篇故事创作，需要在多章节之间保存人物、事件和写作进度。当前实现采用 LangGraph 编排规划、写作和记忆处理；使用三层记忆组织上下文，并通过检查点恢复进度。技术方案、模块关系和流程图见 [长文本生成架构](ARCHITECTURE.md)及 [LangGraph 状态图](LANGGRAPH.mmd)。

| 选型 | 当前用途 | 选用依据 |
| --- | --- | --- |
| LangGraph | 组织写作阶段和条件分支 | 流程和重规划路径可检查，沿用现有 Python 引擎。 |
| 事件先行 | 先组织事件，再编写正文 | 便于追踪人物、物品和时间状态。 |
| 三层记忆与检查点 | 管理上下文、保存进度 | 支持跨章读取与中断恢复；效果仍需通过实验验证。 |
| Chat Completions 接口 | 接入模型服务 | 支持 DeepSeek、OpenAI 和其他兼容服务，具体功能取决于服务商。 |

项目现有技术调研、具体模块和历史方案对照见[技术方案调研报告](../software/architecture.md)。已有验证与限制见[验证记录](../software/VALIDATION.md)；历史实验不应视为当前版本的新增实验结果。
